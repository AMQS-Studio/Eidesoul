# AGENTS

Hard rules and timeless architectural invariants for changes in this repo.

## 1. Language

- English is the default for all code, comments, docstrings, log messages, internal error strings,
  CLI help, prompt scaffolding, model-facing payloads, config comments, tests, and docs.
- Non-English is allowed only in runtime data surfaces: `monoagens/lang/<code>.yaml` (chat catalogs),
  `soul.yaml` persona content, and detector data under `monoagens/library/**`.
- No hardcoded chat-visible string in code: call `t()` from `monoagens/engine/i18n.py` and let the
  catalog supply the text. English code strings are internal diagnostics, never chat replies.

## 2. Boundaries and Architecture

- **Engine is an Autonomous Agent Harness:** Python only. The engine is an appendage-agnostic
  harness maintaining one continuous identity (soul), persistent memory, and access control.
- **Strict Gateway Separation:** Core lives in `monoagens/engine/` and must never import
  `monoagens.gateways`, protocol SDKs (e.g. `neonize`), or gateway-specific implementations.
- **Appendage Contract:** Gateways connect via the inbound contracts in `monoagens/engine/inbound.py`
  (`Percept`, `Address`, `Action`, `Receipt`, `GatewayCore`). Gateways own address normalization
  and transport dispatch; core holds no transport vocabulary or address parsing.
- **Provider Protocol Seam:** Provider adapters in `monoagens/providers/` handle wire facts
  (`openai`, `gemini`, `anthropic`). Engine never performs provider-name comparisons; capabilities
  are declared on `ProviderDefaults`.
- **Async Event Loop Integrity:** Async paths (`async def`) must never be blocked by synchronous
  database transactions, CPU-heavy model embeddings (MiniLM/spaCy), or file I/O. All synchronous
  operations on the turn path must be offloaded via `await io.run(...)`.
- **No Hardcoded Models:** `engine.llm.model` is the operator's choice via configuration.
  Code must never pin or default a specific model ID or force reasoning effort.

## 3. Storage and Process Invariants

- **Dedicated Sovereign Architecture:**
  1 Deployment = 1 Soul = 1 PostgreSQL Database = 1 Primary Process.
  The core schema stays lightweight and scoped to a single deployment.
- **Single Primary Process:** Enforced via `engine_lease` in PostgreSQL with `CheckConstraint("id = 1")`.
  An instance without the lease remains in standby and writes nothing to the database.
- **Single System of Record:** PostgreSQL + pgvector is the sole storage engine. Schema migrations
  go exclusively through the Alembic chain in `migrations/`.
- **Authoritative Configuration:** Host YAML files (`config.yaml`, `roles.yaml`, `soul.yaml`, `.env`)
  are the operator's source of truth; database document rows are derived caches. Secrets live only
  in `.env` and are never committed.

## 4. Memory and Privacy

- **Unified Memory Store:** The `memories` table in PostgreSQL is the single source of truth and
  native hybrid retrieval index (MiniLM `vector(384)` with HNSW + `search_tsv tsvector` with GIN).
- **Single Write Port:** All canonical memory writes pass through `MemoryStore`. Reads for prompt
  assembly go exclusively through `memories_readable`.
- **Layered Privacy (L0–L4):** Evidence is collected deterministically before privacy levels are
  evaluated. Secret credentials (L5) are never stored. The subject of a personal memory holds veto
  power. Memories with level NULL must never be disclosed to LLMs.
- **Cross-Thread Isolation:** Memory queries are strictly scoped to `global` + `person:<sender>` +
  `thread:<active_thread>`. Private memories of other users or threads must never leak.

## 5. Security, Authorization, and Tools

- **Single Outbound Door:** All outbound messages, file deliveries, and side-effecting actions must
  pass through `Agent.dispatch()`.
- **Explicit Origin Required:** The delivery door requires an explicit `origin: Address`. The origin
  must never default to the target address, ensuring cross-room and cross-gateway authorization
  checks are always executed.
- **Role-Based Access Control:** Permissions come strictly from `roles.yaml`. A missing entry denies
  access. `administrator` is the protected top role and must exist.
- **Sandbox Guard & Approval Policy:** Sensitive actions (`shell`, `sandbox`, `settings`) and
  cross-room operations require verification through `SafetyPolicy` and `/approve`.
- **Deterministic Action Idempotency:** Outbound actions generated by tools must use deterministic
  identifiers to prevent duplicate side effects upon turn resume or process restart.

## 6. Extensions and Capabilities

- **Clean by Default:** Gateways, body-specific tools, and plugins are optional extensions and
  are disabled by default until configured and enabled by the operator.
- **Core vs Body Tools:** General tools (`read`, `write`, `web_search`, `send_message`, `send_file`,
  `thread_history`) belong to core tools. Gateway packages only hold tools specific to their own
  physical embodiment or transport actions.

## 7. Verification

- All changes must keep the test suite and static checks clean:
  - `pytest -q`
  - `ruff check monoagens scripts tests plugins migrations`
  - `python -P scripts/types.py --check`
  - `python -P scripts/adr.py --check`
